# 3. Standard Procedures

## 3.1 Moderation Ability Overview

Staff are given moderation abilities appropriate to their role ([Section 2.3](staff-roles-responsibilities.md#23-staff-roles){ data-preview }). These abilities are tools to maintain a fair and friendly server, not privileges for personal use or gain.

General guidelines for using moderation powers:

- If a situation is covered below, follow its specific procedure.

- If not, always use the least severe action necessary (warn → mute → kick → jail → ban) and a reasonable duration.

- Always provide a valid reason when taking action against a player.

- Always document the incident using the Discord staff action process (refer to [Section 4.2](logging-documentation.md#42-send-a-written-warning){ data-preview } or [Section 4.3](logging-documentation.md#43-send-a-disciplinary-action-notice){ data-preview } for processes).

- When in doubt, escalate the issue up the [chain of command](staff-roles-responsibilities.md#21-chain-of-command){ data-preview }.

---

## 3.2 Situation Specifics

Use these procedures to respond consistently to player reports and server incidents. Choose the situation below, take the least severe effective action, and record what happened. Refer to [Section 4.4](logging-documentation.md#44-incident-records){ data-preview } for viewing a player's previous warnings or actions.

### 3.2.1 Server Crashes { .situation-heading }
??? info "3.2.1 Server Crashes"

    - Mods/Admin → Immediately notify a Developer or Committee Lead.

    - Check Discord staff channels for updates from the technical team.

    - Do not attempt fixes beyond your permissions (e.g., restarting the server via Apex if you do not have access).

    - Devs/Lead → Look in console for any errors and reference plugin documentation as needed.

    - Indentify a soluation as soon as possible, even if it's a tempoary fix to get the server running in the meantime.

    - If the server remains down for more than 15 minutes, a Developer or Lead should make a public announcement.

    - Log the issue using the staff action center in Discord. Follow up with another annoucment once the server is restored.

### 3.2.2 Staff Member Abuses Power { .situation-heading }
??? info "3.2.2 Staff Member Abuses Power"

    - Collect evidence (screenshots, chat logs, recordings, etc.)

    - Immediately escalate to the Server Lead for investigation.

    - If the Server Lead is the one abusing power, escalate the situation to the ERRSA Executive Board.

    - Never confront staff members publicly; always handle it internally.

    - Server lead → Review evidence and determine appropriate action, follow [Section 6.2](6-staff-advancement-and-governance.md#62-demotions-removal){ data-preview } if needed.

    - Log any relevant information after the situation is concluded.

### 3.2.3 Inappropriate Language { .situation-heading }
??? info "3.2.3 Inappropriate Language (Chat/Signs/Books)"

    - In most cases, the auto filter plugin should censor inappropriate language, though some leniency is allowed.

    - If player's attempt to bypass the filter becomes excessive, send a formal warning to the player following [Section 4.2](logging-documentation.md#42-send-a-written-warning){ data-preview }.

    - If offense is through signs, books, etc. remove the offensive materials.

    - If the behvaior continues, issue a temporary mute to the player and send formal communication following [Section 4.3](logging-documentation.md#43-send-a-disciplinary-action-notice){ data-preview }.

        - First offense, 24 hour

        - Second offense, 1 week

        - Third offense, permanent

    - **Severe cases (hate speech, slurs, etc.)**

        - Issue a permanent mute and escalate the situation to the Server Lead.

        - Server Lead → Follow [Section 4.5](logging-documentation.md#45-student-conduct-escalation){ data-preview } for reference on student conduct escalation.

    - If the offense occurs through **proximity voice chat**:
      
      - Follow the same disciplinary progression, but substitute temporary bans for mutes of equivalent duration, as standard mutes do not affect proximity voice chat.

    - **Severe cases (hate speech, slurs, etc.):**
      - Escalate to the server lead

    - Document the incident thoroughly following [Section 4.4](logging-documentation.md#44-incident-records){ data-preview }.

### 3.2.4 Inappropriate Behavior { .situation-heading }
??? info "3.2.4 Inappropriate Behavior (Harassment, Toxicity, etc.)"

    - If the offense is through chat, refer to [Section 3.2.3](standard-procedures.md#323-inappropriate-language){ data-preview } for further instructions.

    - If the behavior is minor, send a formal warning to the player following [Section 4.2](logging-documentation.md#42-send-a-written-warning){ data-preview }.

    - If the behavior continues, issue a temporary ban to the player and send formal communication following [Section 4.3](logging-documentation.md#43-send-a-disciplinary-action-notice){ data-preview }.

        - First offense, 24 hour

        - Second offense, 1 week

        - Third offense, permanent

    - In severe cases,

        - Issue a permanent ban and escalate the situation to the Server Lead.

        - Server Lead → Follow [Section 4.5](logging-documentation.md#45-student-conduct-escalation){ data-preview } for reference on student conduct escalation.

    - Document the incident thoroughly following [Section 4.4](logging-documentation.md#44-incident-records){ data-preview }.

### 3.2.5 Inappropriate Builds { .situation-heading }
??? info "3.2.5 Inappropriate Builds"

    - Mods → Gather evidence and screenshots then escaluate the situation to an Admin or above.

    - Admin/Dev → Gather evidence,screenshots, and use investigation tools to determine the player who built the structure.

    - Destroy the structure if possible and replace it with a sign stating, “Inappropriate builds are a violation of our rules. Please remain respectful on the server.”

    - If the behavior is minor, send a formal warning to the player following [Section 4.2](logging-documentation.md#42-send-a-written-warning){ data-preview }.

    - If the behavior continues, issue a temporary ban to the player and send formal communication following [Section 4.3](logging-documentation.md#43-send-a-disciplinary-action-notice){ data-preview }.

        - First offense, 24 hour

        - Second offense, 1 week

        - Third offense, permanent

    - In severe cases,

        - Issue a permanent ban and escalate the situation to the Server Lead.

        - Server Lead → Follow [Section 4.5](logging-documentation.md#45-student-conduct-escalation){ data-preview } for reference on student conduct escalation.

    - Document the incident thoroughly following [Section 4.4](logging-documentation.md#44-incident-records){ data-preview }.

### 3.2.6 Cheating, Hacking, or Exploiting { .situation-heading }
??? info "3.2.6 Cheating, Hacking, or Exploiting"

    - Mods → Immediately escaluate the situation to an Admin or above.

    - Admin/Dev → Use investigation tools to gather initial evidence (screenshots, videos, plugin alerts, anti-cheat logs, etc.)

    - Once potential suspects are identified, issue a jail until proven innocent or guilty while further investigation continues.

    - Continue the investigation, speak with involved players directly for their side of the story, and put evidence together to determine the full picture.

    - Issue a temporary ban to any players found guilty and send formal communications following [Section 4.3](logging-documentation.md#43-send-a-disciplinary-action-notice){ data-preview }.

        - First offense, 1 week

        - Second offense, 1 month

        - Third offense, permanent

    - If the case is extreme where the server's or player's data is in harm, issue a permanent ban.

    - Unjail all suspects, including those who have been banned.

    - Send formal communication to the involved players following [Section 4.3](logging-documentation.md#43-send-a-disciplinary-action-notice){ data-preview }.

    - Document the incident thoroughly following [Section 4.4](logging-documentation.md#44-incident-records){ data-preview }.

    - Always report exploits that affect server stability or fairness to a Developer.

### 3.2.7 Griefing or Theft { .situation-heading }
??? info "3.2.7 Griefing or Theft"

    - If a player is actively griefing or stealing, issue a jail while relevant information regarding previous ban history is gathered.

    - Mod → If the situation requires investigation, escalate to an Admin or above.

    - Admins → Use investigation tools to determine who caused the damage, or took the stolen items. Verify claim and ownership of builds or items.

    - Admins → Some guess work may be necessary, use your best discretion and ask, “what is most likely to have occurred?”

    - Admins → Restore damages or give items whenever verifiable. Again, use best discretion if needed.

    - If the behavior is minor, issue a formal warning to the player following [Section 4.2](logging-documentation.md#42-send-a-written-warning){ data-preview }.

    - If the behavior continues, issue a temporary ban and send formal communication following [Section 4.3](logging-documentation.md#43-send-a-disciplinary-action-notice){ data-preview }.

        - First offense, 24 hour

        - Second offense, 1 week

        - Third offense, permanent

    - Unjail any players, including those who got banned.

    - Document the incident thoroughly following [Section 4.4](logging-documentation.md#44-incident-records){ data-preview }.

### 3.2.8 Spamming or Advertising { .situation-heading }
??? info "3.2.8 Spamming or Advertising"

    - Refer to [Section 3.2.3](standard-procedures.md#323-inappropriate-language){ data-preview } for further instructions.

### 3.2.9 Lag Machines { .situation-heading }
??? info "3.2.9 Lag Machines"

    - If the machine was created accidentally, Ex. Making a complex redstone farm, send a custom communication following [Section 4.7](logging-documentation.md#47-sending-custom-communications){ data-preview }, and ask them to remove the machine.

    - If the behvaior continues, or the machine was created for intentional lag purposes, issue a temporary ban and send formal communication following [Section 4.3](logging-documentation.md#43-send-a-disciplinary-action-notice){ data-preview }.

        - First offense, 24 hours

        - Second offense, 1 week

        - Third offense, permanent

    - Admins → Use creative or other plugin tools (such as world edit) to dismantle the machine as needed.

    - Document the incident thoroughly following [Section 4.4](logging-documentation.md#44-incident-records){ data-preview }.

    - Dev/Lead → In severe cases where connecting to the server is not possible, a server roll back or external tools may be necessary to dismatle the machine. Use this only as a last resort.

### 3.2.10 Player Disputes { .situation-heading }
??? info "3.2.10 Player Disputes / Drama"

    - Encourage players to resolve their disputes respectfully.

    - If any rules are being violated (toxic chat, harassment), refer to [Section 3.2.3](standard-procedures.md#323-inappropriate-language){ data-preview } or [Section 3.2.4](standard-procedures.md#324-inappropriate-behavior){ data-preview } based on what is more appropriate.

    - If players ask for staff assistance, attempt to mediate the situation

        - When disputes remain civil but unresolved after attempted staff mediation, escalate to the Server Lead for assistance.

        - Server Lead → Determine appropriate course of action for finding a resolution.

    - If staff were involved or helped mediate in any situation, document the incident thoroughly following [Section 4.4](logging-documentation.md#44-incident-records){ data-preview }.

## 3.3 Ban Appeals

- Appeals **must** be submitted through the [Official Appeal Form](https://forms.fillout.com/t/aqN78Bu5osus) which can be found in the welcome channel on Discord, or in the player's student email after a formal written statement has been issued.

- Appeals will be reviewed by the committee lead, and if appropriate for an appeal, voted on by the staff team to determine a decision.

- Staff who issued the punishment may provide additional context if called upon.

---

## 3.4 Suggestion Forms

- Suggestions *should* be submitted through the [Official Feedback Form](https://forms.fillout.com/t/s2oKYJtMGDus) which can be found in the welcome channel on Discord, or with `/feedback` in game. Though feedback is encouraged though any media.

- Developers review technical suggestions (plugins, builds, gameplay).

- Committee Lead reviews staff and rule-related suggestions.

- All suggestions should receive a staff response, even if denied, to maintain transparency.

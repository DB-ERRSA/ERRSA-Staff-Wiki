# Developer Assessment

This is a **provisional assessment outline** for the future Developer learning track. It does **not** authorize production changes or establish a new promotion requirement. The Server Lead and Developers should validate the exercises against the eventual Developer modules before using it for a formal decision.

## 1. Diagnosing a Startup Failure

A backend fails immediately after an update. Explain how you would identify the first relevant error, dependencies, affected backend, and an appropriate rollback path without improvising live fixes.

## 2. Permissions and World Context

A command works in Workshop but not Survival. Explain how you would compare LuckPerms server/world contexts with plugin configuration, and why broad wildcard permissions are a risky shortcut.

## 3. Safe Configuration Changes

Describe how you would back up and review a proposed plugin configuration change, test it away from production, obtain approval, and verify it after deployment.

## 4. Incidents and Player Data

Players report an inventory change after world teleportation. Outline evidence preservation, Multiverse-Inventories group/profile checks, data protection, and restoration approval before modifying live player data.

## 5. Communication and Handoff

Describe what a Developer should include in a technical incident handoff, including logs, affected systems, changes made, testing, rollback plan, and unresolved risks.

!!! warning "Requires Developer track review"
    The Developer learning modules are not currently published in the wiki navigation. An experienced Developer and the Server Lead must approve an assessment rubric before this can become a required check.

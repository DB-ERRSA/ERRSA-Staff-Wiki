# Assessment Process

**Moderator, Admin, Developer, and Server Lead candidates must complete an assessment before appointment or promotion.** Candidates complete the relevant learning material and demonstrate the judgment and skills expected for the role.

## Role Assessments

| Admin | [Admin Assessment](admin.md){ data-preview } |

| Server Lead | [Server Lead Assessment](server-lead.md){ data-preview }; [election](../../documentation/6-staff-advancement-and-governance.md#64-server-lead-selection){ data-preview } also required |

## Process

1. **Prepare.** Complete the relevant learning modules and review any lower-role procedures needed for the position.
2. **Assess.** An assigned reviewer conducts the role scenarios and any supervised practical tasks. Candidates may consult the wiki; decisions and safe execution matter more than command memorization.
3. **Record.** The reviewer privately records outcomes, gaps, and any practical demonstrations. Answers, scoring guidance, and completed records are not published in the wiki.
4. **Decide.** The Server Lead approves role assignments and promotions after a satisfactory assessment. Server Lead selection also follows the formal election procedure. **Passing does not automatically grant a role or permissions.**

Use **Demonstrated**, **Needs practice**, or **Not yet tested** for each assessed area. Where practice is needed, the reviewer sets a follow-up assessment before approval.

## Practical Demonstrations

The reviewer selects appropriate exercises for the role. Admin assessment includes supervised CoreProtect investigation and restoration, claim access, diagnostics, jail/release, and incident coordination. Developer assessments include controlled troubleshooting, permission/context checks, change testing, and incident handoff. Moderator assessments include live-incident decisions, escalation, and records. Test actions must use approved test environments and consenting test accounts.

Temporary elevated access for an exercise requires explicit Server Lead approval, followed by verified removal. No training exercise authorizes changes to unrelated live player data.

## Private Assessment Record

Keep one record per candidate in approved private staff storage containing the candidate and target role; reviewer and dates; completed modules; scenario/practical results; evidence references; remaining gaps; any temporary access granted and removed; recommendation; and final approval or follow-up decision.

!!! important "Separate restoration authorization"
    Admin assessment and role assignment do not authorize independent CoreProtect rollbacks or complex item reconstruction. Independent restoration requires separate recorded Server Lead approval after supervised practice; complex item recovery also requires an approved procedure and explicit authorization.
